01｜三条提示词，Simon Willison 做出可分享的 LaTeX 渲染器

谁·场景
开发者 Simon Willison，看到 Paul Ford 团队的 Tiny Little Office 后，想给自己的 tools 仓库加一个 LaTeX 工具。
怎么用
用 Claude Code（Opus 5.5 Extra）。第一条提示词写清功能规格，后两条让它照搬仓库里已有工具的 iframe 沙箱和 Gist/URL 加载功能。
结果
做成的工具能把 LaTeX 放在网址 # 后面直接渲染，可以收藏、分享，也能切回源码编辑。依赖 Pako、MathJax、faster-latex 和 DOMPurify 这几个库。
你可以试
让 agent 写新工具时，点名仓库里哪个旧工具可以参考，让它复用已经验证过的写法。前提是你手上有一批自己维护的小工具或代码。
注意
安全问题是他主动提出的，第一条提示词没提，agent 也没有自己去做。手上没有可参考的旧代码时，这类约束要自己写进规格。

Simon Willison 在本人博客记录了一个小工具的做法。灵感来自 Tiny Little Office：这套网页版办公工具把文档数据全部存在 URL 的 #fragment 里，每份文档都是一个能收藏、能分享的链接。它还提供 llms.txt，告诉 agent 怎样拼出能渲染成文档的网址。Claude 就靠这个文件生成了一份讲 URL 格式的幻灯片。

他给 Claude Code 的提示词一共三条。第一条是完整规格：读取 # 后面的内容按 LaTeX 渲染；支持一个前缀，表示内容用专为 LaTeX 优化的自定义字典压缩过；从 CDN 选最好的渲染库，WebAssembly 也可以考虑；没有 # 时显示编辑器，可以切到渲染视图，渲染视图要能收藏。第二条问安全：能不能防 XSS？可以像 SVG in Markdown 工具那样用 iframe sandbox。第三条要复用：照那个工具的做法，支持从 URL 或 Gist 加载。

可以借鉴的是后两步。agent 在你自己的仓库里工作，“参考某某工具的做法”比从头描述需求更短，也更可靠。适合已经积累了一些内部小工具的工程师、分析师。把数据放进网址也省掉了后端和存储，做团队内部分享用的小页面可以先试这个结构。

02｜Claude Code 团队：别再问“有没有人看过代码”

谁说的
Anthropic Claude Code 团队的 Addy Osmani、Morgan Westlee Lunt 和 Qing Wang，在文章《How the Claude Code team does code review》中介绍团队做法，Simon Willison 于 10 月 16 日摘录。
核心观点
他们认为“有没有人读过代码”只是一个粗糙的替代指标。该问的是：这次改动可能出什么问题？由哪一道检查来拦，自动的还是人工的？
依据
审查从提 PR 之后的关卡，变成写代码时持续进行，他们比作拼写检查。他们说常规错误大多被 Claude 先拦下，团队的注意力留给更高层的问题。
对你的意义
把审查清单按风险重新分一遍：哪些交给 AI 或自动检查，哪些必须由人判断。这能用在代码上，也能用在文档、数据报表上。
争议·条件
他们只说 AI 能拦下“大多数常规错误”，高层判断仍然靠人。这套做法建立在团队对 Claude Code 很熟、自动检查齐全的基础上。

Simon Willison 摘录了 Claude Code 团队的一段话。他们说，以前的审查是流程末尾的关卡：写代码、开 PR、等同事看。现在换了一个问题来问：这个改动可能出什么错，哪一道检查最适合拦住它？ 问题换了，审查的时机也跟着变了，变成写代码时持续在跑，像拼写检查。大多数改动在请人看之前，已经被 Claude 审过、修过至少一次。

同一天，Every CEO Dan Shipper 在 X 上写道：生成内容现在便宜，质量也高，接下来最需要提升的能力是编辑和监督。两边说的是同一件事：瓶颈从“写出来”移到了“查得对”。

对带团队或自己写代码的人，可以先列出常见错误，把能由机器发现的那部分前移到写作过程中，人工审查只留给设计取舍、需求理解这类问题。这套分工依赖可靠的自动检查。测试薄弱的项目照搬，等于少了一道人工关卡，却没有补上别的检查。

03｜零代码基础做健身 App，三分之一收入来自 X

谁·场景
Max，没有编程经验，做了举重训练 App Maxed.ai，在 Starter Story 的短视频中分享获客经验。
怎么用
他的做法是：早期先不请 UGC 创作者，等摸清哪些切入角度能带来下载再说；投放选 Meta 而不是 TikTok；利用切片短视频（clipping）拿到海外曝光和自然下载。
结果
标题称他的月经常性收入为 1.3 万美元。他说三个月前开始发推，现在约三分之一收入来自 X 上的用户。
你可以试
花钱请创作者之前，先自己发几种不同角度的短内容，看哪种带来下载。同时在 X 上公开记录做产品的过程。
注意
Meta 和 TikTok 的对比，依据是他自己对用户付费意愿的判断，适合他这类付费订阅的健身工具。他没有给出投放花费和转化数字。

Starter Story 的短视频里，Maxed.ai 创始人 Max 讲了现阶段该把力气花在哪。他没有编程经验，做出了这个举重 App。他的判断是 Meta 的流量比 TikTok 更值钱：“用户购买意向更高……付费意愿也更高。”他还说切片短视频“真的爆发了”，现在入场仍然能赚到钱，也是拿到海外曝光和自然下载的好办法。

顺序值得记下：先找到能带来下载的切入角度，再花钱请 UGC 创作者放大。角度没验证就付费，等于花钱试错。另一个点是 X：他三个月前才开始发推，现在约三分之一收入来自那里。对独立开发者来说，公开记录做产品的过程本身就是一个获客渠道，成本几乎只有时间。

04｜七个 ChatGPT 插件，帮他找歌、挑电影、学下棋

谁·场景
Tom's Guide 作者 Elton Jones，通勤要听音乐，周末想找冷门电影，也玩游戏、看漫画。
怎么用
在 ChatGPT 里用 Spotify、Apple Music、Tubi、Flixor、GameFinder、Emaqi、Chessy 插件。交给 AI 的只有他喜欢的艺人、作品和类型，提示词要求解释推荐理由、排序，并标出冷门选项。
结果
他说因此发现了 Gareth Donkin、Smino 等歌手，用 Tubi 找免费电影安排周末，用 Chessy 一边下棋一边学。
你可以试
套用他的模板：列出三到五个最喜欢的作品，要求 AI 按氛围、叙事等维度分析，给出排序，并至少包含几个冷门选项。
注意
推荐结果他会先查评价再采用，这一步仍然要自己做。实体碟片、其他平台的漫画，还要自己去找购买或阅读渠道。

Elton Jones 在 Tom's Guide 列出了他每天用的七个 ChatGPT 插件，以及每个插件最好用的提示词。他的模板有共同点：给出具体喜好，要求说明理由，要求排序，并指定冷门推荐的数量。比如找电影时，他让 AI 按氛围、叙事、人物塑造和反转来匹配，不只看类型。用 Tubi 时，他让 AI 安排一个免费电影之夜，并分出适合轻松看和认真看的片子。

下棋插件 Chessy 的提示词也能用在别处：说明自己是新手，让 AI 每步之后指出一个做得好的地方、一个要注意的错误。拿来学任何新技能都可以试试。他的习惯是先查评价再采用推荐，然后转给朋友。这里交出去的只是兴趣偏好，不涉及账户和财务数据，风险很低。

今天可以做的一件事

从这周要交的一件工作里挑一份产物，可以是代码、方案文档或数据报表。交给别人看之前，先让 AI 按“这份东西可能在哪里出错”审一遍，并要求它把问题分成两类：自己能确认的，和需要人来判断的。改完后记下 AI 拦住了几处错误、哪些问题只有你或同事能发现。攒上三五次，你就有一份按风险分工的审查清单，知道哪些检查可以交出去，哪些必须留给人。
