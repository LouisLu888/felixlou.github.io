01｜Reddit 自建 AI 原型工具，700 多个原型直接用真实数据

谁·场景
Blair Metcalf，Reddit principal UX engineer，在 Claire Vo 的 How I AI 节目里演示他搭的 vibe-coding 原型工具 Reddit Proto。
怎么用
他做了一个 design system MCP，把 Reddit 的产品设计语言对应到生产代码。原型接的是真实 Reddit 数据。在原型上做的标注会变成 Cursor 里一次定向的代码修改，交给工程师时整体打包成一个「feature capsule」。
结果
节目里称 Proto 在 Reddit 的 UX 和产品组织里达到 100% 采用，在线原型超过 700 个。设计师可以把原型安全地分享给管理层，管理层直接在上面评审、给反馈。
你可以试
团队有设计系统和组件库的话，先整理一份「设计稿组件名 ↔ 代码组件」对照表（他叫它 Rosetta stone），让 Cursor 生成原型时直接调用真组件。
注意
这套做法要有成熟的设计系统、内部部署设施和真实数据的访问权限。小团队缺这些条件，可以先只做对照表这一步。

在 How I AI 这期节目里，Blair Metcalf 演示了 Reddit Proto。这是 Reddit 自己搭的 vibe-coding 工具，核心是一个 design system MCP，作用是把 Reddit 的产品语言对应到生产代码。节目里给出的数字是：UX 和产品组织 100% 采用，在线原型超过 700 个。内部部署参考了 Vercel 的思路。

可以借鉴的是这条链路：用真组件、接真数据，在原型上标注，再转成 Cursor 里的定向修改，最后打包交给工程。 他认为真实数据比 mock 数据好用。原型看着像真产品，管理层的反馈会更具体；交接时工程师拿到的也是能用的代码。他还专门做了一份「Rosetta stone」，把设计语言和代码一一对上。AI 生成跑偏时，这份对照表就是纠正的依据。

这套东西靠的是 Reddit 已有的设计系统和基础设施。普通团队可以先拿最常用的二三十个组件做对照表，试一个页面。演示从 02:31 开始，标注转 Cursor 修改在 09:15，MCP 怎么搭的在 17:50。节目还讲到谁后来成了 Reddit 最会做原型的人，带团队的人可以留意这一段。

02｜用 Claude 做短视频：照参考片换风格，拿会议笔记出片

谁·场景
Jake Moran 在 HyperFrames 团队，Peter Yang 转发了他的演示。另一个例子是 Every 的 Mike Taylor，在节目片段里讲自己怎么用。
怎么用
在 HyperFrames studio 里上传或选一段参考片，提示词写清要改哪里，比如换字体、换颜色，结构照原样保留。Mike Taylor 则把 Slack 消息和会议笔记交给 Claude Opus，让它组装素材并剪辑成讲解视频。
结果
Peter Yang 说几分钟就能复刻一种短视频风格。Mike Taylor 从日常沟通记录里得到了一支讲解视频。
你可以试
挑一支你认可的同领域短视频当参考，只换字体和配色，做一版自己的内容。也可以把一周的会议笔记交给 Claude，先让它出讲解视频的脚本和分镜。
注意
能复刻的只是结构和视觉，选题和观点还得自己出。套用别人的风格容易撞款，要留出自己的辨识度。

Peter Yang 在 X 上转发了 HyperFrames 的 Jake Moran 的演示。复刻风格已经是 HyperFrames studio 的内置功能：上传或选一段参考片，在提示词里描述要改的地方，比如换字体、换配色。Jake Moran 的原话是「结构上还是同一个想法」。另一个例子来自 Every 的短片：Mike Taylor 把 Slack 消息和会议笔记交给 Claude Opus，由它组装并剪辑一支讲解视频。

两件事加起来，短视频制作可以拆成两块：内容来自你本来就有的工作记录，形式参考一支验证过的样片。做一条视频的成本降下来以后，Zara Zhang 同一天在 X 上说的那套打法就做得起了：搭一个每天出一条视频的系统，这比花几万美元做一支发布视频更有用。她认为很多人高估了一次大发布，低估了每天在时间线上露面。

适合已经有素材积累、想稳定更新的人，比如做产品、做咨询，手里有大量会议纪要和项目记录。复刻风格只是起点，观众留下来还是看内容。

03｜Box CEO：安全 agent 刚能用，先把数据底子理顺

谁说的
Aaron Levie 是 Box CEO，2026-10-25 在 X 上评论大企业安全的现状。
核心观点
他认为企业的风险面会越来越碎：数据分散，有的系统权限开得太宽，有的系统主要靠「没人知道」来保证安全。基础设施理顺以后，agent 群可以并行调用各种安全工具、测试各种攻击变体、读日志，还能评估企业数据的风险等级。
依据
他的依据是一线观察：大企业连库、工具和基础设施的更新都跟不上，初创公司和非科技公司更难。他说长时运行的 agent 和够用的 computer use 是最近几个月才成熟的，之前做不到。
对你的意义
做 AI 咨询的人可以从数据梳理和权限盘点切入，这比一上来就卖 agent 更容易落地。他点名的机会覆盖身份、防火墙、网络、代码扫描、数据保护各层。
争议·条件
这是他的判断，落地还没有普及。前提是数据和基础设施先完成现代化，很多非科技公司离这一步还远。同样的能力也会落到攻击方手里，他的乐观只针对攻防平衡这一点。

Aaron Levie 在 X 上描述了大企业安全的现状：要跟进的库没完没了，基础设施、数据和代码越铺越大，多数大企业都跟不上。数据分散，企业在任何时刻都说不清自己的风险状态。有的系统权限开得太宽，有的主要靠 security through obscurity。

他的判断分两步。第一步是先做基础工作，让数据和基础设施现代化。第二步才轮到 agent 群：并行调用安全工具、测试攻击变体、读日志、给数据评风险。他说这类能力是最近几个月才有的，靠的是长时运行的 agent 和够好的 computer use，并认为这是他对攻防平衡保持乐观的一个理由。

对想做 AI 咨询的人，这段话指了一个顺序：客户最先缺的往往是数据盘点、权限梳理、系统清单，这些活现在就能接，而且是后面上 agent 的前提。从身份到数据保护，他认为安全栈的每一层都有机会。这是 10 月 25 日的个人判断，具体到某个客户，还要看对方的基础设施成熟到什么程度。

今天可以做的一件事

打开你们团队最常用的设计稿或文档模板，列一张对照表：左边写团队平时怎么叫一个组件或模块，右边写它在代码库或系统里的真实名字，先列 20 个。下次让 Cursor 或 Claude 生成原型、写方案时，把这张表一起给它，对比一下产物离「能直接用」近了多少。表里对不上的地方，就是团队设计和工程之间要先补的沟通。
