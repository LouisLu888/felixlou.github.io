01｜给达拉斯水管工查网页漏洞，提案里一个 AI 都不提

谁·场景
James Dickerson（网名 Boring Marketer）在北卡 Charlotte 经营流动柴油车维修公司 Diesel Dudes，此前多年给本地商家做代理商，也是主持人 Greg Isenberg 的生意伙伴。
怎么用
他在 Claude Code 里搭了一套 MCP 工具（Boring Funnels），从 Google Maps、Yelp 等来源抓取商家信息，按评论数、技师人数和营收线索筛选客户。工具接着自动审查对方的广告和落地页，生成带对方品牌的提案。
结果
他说，约 1 分钟找到 100 家水管公司，约 15 分钟后提案和联系邮箱都已备好。他抽查的 5 家都在投 Google 广告，Google 评分在 4.8 到 4.9 之间。其中 4 家的落地页没有重复广告里的承诺，3 家没展示 Google 评分，4 家要翻三屏以上才能预约。
你可以试
选一个客单价高的本地行业和一个城市，用 AI 把 20 家正在投广告的公司按上面三项检查一遍，整理成截图对比。然后免费给其中一家重做一个页面，换一份案例。
注意
他瞄准的是年营收 200 万到 2000 万美元的商家，取得这些老板的信任要花几个月。他自己试过让 AI 前台接电话，很多来电者问一句「这是不是个蠢 AI」就挂了。

在 Startup Ideas Podcast) 里，James Dickerson 讲了给本地工种公司做服务的一套打法。他的判断是，这些公司已经在花钱买流量，问题出在落地页上。他估计，一家年营收 500 万美元的水管公司每年营销支出在 15 万到 25 万美元之间，而代理商做一个好的漏斗要收 2 万美元。会用 coding agent 的人，可以把这件事做得又快又好。

他卖的是预约单和来电，不讲 AI，因为很多老板分不清 AI agent 和房产中介 agent。交付的是一组漏斗：79 美元的保养引流单、页面上直接报价、「修还是换」测评问卷，以及老板出镜讲解 2 万到 3 万美元的换机决策。不同搜索词的广告对应不同的页面。他说大多数公司把所有流量都导到同一个页面。

获客用 Chet Holmes 的 Dream 100：先列出 100 家目标公司，让 AI 去读评论、爬网站、查老板背景，然后每周给这些人提供有用的内容。他还会寄「lumpy mail」，比如一个盒子里装一枚黄铜管件，附上已经替对方重做好的页面链接。他强调这要做很久才见效，第一单可以用一次免费搭建换一份案例。

02｜Reddit 让设计师不碰 Git，做了约 700 个真数据原型

谁·场景
Blair Metcalf 是 Reddit 首席 UX 工程师，在 How I AI 节目里演示了他做的内部工具 Reddit Proto。
怎么用
桌面应用在后台处理仓库、分支和脚手架，原型可以用真实的 Reddit 账号登录。设计师写的批注会连同对应组件和设计规范一起发给 Cursor。团队还自建了设计系统 MCP，把 token 和组件对应到生产代码。
结果
他说团队已做出约 700 个原型，UX 与产品团队采用率 100%。用得最好的人里，有没有工程背景的视觉设计师和动画师。
你可以试
先把团队的组件库和设计规范整理成 AI 能读的文档或 MCP，再让 Cursor 按它改一个现有页面，检查它有没有用对组件。
注意
前提是公司已有成熟的设计系统，还有一位工程师专门搭建和维护这套平台。原型做多了以后，找到已有的原型也成了问题，Reddit 正在做可搜索的原型目录。

How I AI 本期里，Blair Metcalf 演示了 Reddit Proto。设计师和 PM 不用碰 GitHub，就能做出接近线上产品的原型。原型可以用真实账号登录，信息流、搜索和社区里都是熟悉的内容，管理层评审时不用在脑子里替换占位数据。

关键是让 AI 带着上下文改代码：每条批注都附上对应的组件、设计系统规范和用户意图，再交给 Cursor。设计系统 MCP 告诉 Cursor 该用哪个组件、长什么样、代码放在哪里。交接环节叫「feature capsule」：设计师提交 Figma 链接，系统把每个元素对应到生产组件，结合以往的工程反馈，生成带验收标准的 PRD。

小团队照搬整套平台不现实，但其中两点可以先试：给 AI 的输入要包括组件和规范，交给工程的需求要写明验收标准。

03｜断网的喜马拉雅山脚下，笔记本上的本地 agent 修好了 bug

谁·场景
Rittika Jindal 是 Thomson Reuters 首席工程师，一年前搬到喜马拉雅山脚下，那里常断网、断电。
怎么用
Ollama 在本机运行 Qwen3.5 9B，OpenCode 作为终端里的 coding agent。配置里只启用本地模型，编辑文件和执行命令前都要确认，网页工具也被屏蔽。
结果
一个记账函数每次循环都覆盖总额，agent 把 total = 改成 total +=，五个测试全部通过，作者之后又自己跑了一遍测试核对。agent 起初想用 pytest，而项目用的是 unittest。
你可以试
如果你常在飞机或火车上写代码，联网时先拉好模型和依赖，在一个有现成测试的小项目上试一次。提示词里写明准确的测试命令。
注意
9B 模型下载约 6.6 到 7.6 GB，作者引用的估算是需要 12 到 16 GB 内存，开 64k 上下文还要更多。离线时装不了新包，也查不了网页。演示用的是一个范围很小的 bug。

Rittika Jindal 在 Latent Space 的文章里一步步记录了离线配置：联网时装好 OpenCode 1.19.4，用 Ollama 拉取 qwen3.5:9b，并让 Ollama 只监听本机、关闭云功能。然后关掉 Wi-Fi，先用 curl 确认本地服务还能响应、外部地址访问失败，再开始干活。

她的做法里有两点值得照搬。第一，先让测试失败，再让 agent 修：三个用例失败给了 agent 明确的目标，也让人可以不看它的解释，直接用测试检查结果。第二，权限确认是人工检查点：agent 提议跑 pytest 时，她在确认环节发现命令不对。

她也引用了一项研究：在云端模型上，OpenCode 每解决一个任务消耗的 token 约为 Goose 的 40 倍。本地运行不按 token 计费，但上下文长度会占用内存。

04｜Cal AI 给网红付多少钱：先算每千次播放能带来多少收入

谁·场景
Jake 负责 AI 卡路里记录 App Cal AI 的网红营销，在 App Masters 播客里讲了他们的计算方法。
怎么用
跟网红谈跨平台发布的打包价，用「底价＋按播放量的奖励」结构付费，用 RPM 推算最多能付多少钱。
结果
Cal AI 把播放奖励封顶在约 100 万次附近。他的解释是，视频火了以后会传到更宽泛的人群，新增播放的价值随之下降。
你可以试
用你已有的一两次网红合作数据，算出每千次播放带来的下载和收入，再定下次合作的底价和奖励上限。
注意
前提是能把下载和收入对应到具体视频。几百万条视频同时在传播时，归因本身就是难题。

在 App Masters 这期节目里，Jake 把问题从「该付多少 CPM」改成了「这些播放带来的收入，允许我付多少」。按这个思路，底价负责保底，奖励跟播放量挂钩，到一定量级就封顶，避免爆款视频把单次合作做亏。

做付费 App 的小团队可以先跑几次小额合作，记录播放、下载和收入，用早期数据定出自己的 RPM，再整理成能重复执行的合作条款。节目还区分了投放广告、网红合作和 UGC 三种渠道。

05｜Anthropic 招股书：财富 500 强在它身上的花费不到总支出的 0.1%

谁说的
Aaron Levie 是 Box CEO，2026-10-26 在 X 上评论 Anthropic 的 S-1 招股书。
核心观点
他认为，前沿用户和其他公司之间差距很大。目前大企业的这部分支出主要用在写代码和员工个人提效上，等企业为 agent 重新设计业务流程，用量会大幅上升。
依据
他的依据是招股书里的数据：财富 500 强客户平均花费不到总支出的 0.1%。投资人 Nikunj Kothari 同日整理了同一份招股书：Anthropic 每 1 美元计算和基础设施支出带来的收入，从 2025 年二季度的 0.57 美元升到 2026 年二季度的 2.08 美元。
对你的意义
盘点一下你团队的 AI 用法，看是否还停留在有人提问、AI 才回答的阶段，再挑一个可以让 agent 在后台批量处理的流程试点。
争议·条件
「涨 10 到 50 倍」是 Levie 的预测。他自己也说，token 降价和其他大额支出不会消失，这个比例迟早会到顶。

Aaron Levie 在 X 上说，这是招股书里最关键的数字。他判断，现在只有极少数公司真正让 agent 在后台大量处理任务，不需要人去提示。批量处理数据、多个 agent 并行写代码、在流程里自动执行任务，这类用法消耗的 token 要多出约 100 倍，也更容易直接算出投入回报。

Nikunj Kothari 的拆解给了另一面的数据：上半年约 80% 的收入按用量计费，而算力合同大多一签就是好几年。

对读者来说，这组数字有两层意思。大公司里愿意动手改造流程的人仍然不多。能把一个流程改成 agent 在后台跑、人做判断的人，在组织里会越来越稀缺。

今天可以做的一件事

找一家你所在城市正在投 Google 或 Meta 广告的本地服务商，比如水管、空调或牙科，点开它的广告落地页，按三项检查一遍：页面有没有重复广告里的承诺，有没有展示 Google 评分，需要往下翻几屏才能预约。各截一张图，再让 AI 根据截图写一版改进后的首屏文案。这一页对比图，可以成为你的第一份案例，也可以成为你和这位老板开口聊的理由。
