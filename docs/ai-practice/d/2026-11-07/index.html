01｜一个人拍 AI 科幻剧集：哪些环节交给模型，哪些还得自己做

谁·场景
Theoretically Media 频道主 Tim Simmons，自编自导 AI 科幻系列 Planet Hell，第一集发布后公开幕后流程。
怎么用
Gemini 4 Argon 把两年的笔记整理成十集路线图；在 OpenArt 上用 Seedance 2.5 生成镜头，部分通过 MCP 从 Claude Code 和 Codex 调用；After Effects 里的抠像由 Claude 完成；Gemini 4 读取 Premiere XML，在 DaVinci Resolve 里调色混音；配乐用 Suno。
结果
第一集已经上线。他总结了三条经验：镜头不交给机器决定，能局部修就别整段重新生成，一个人现在已经能把片子做出来。
你可以试
先建一个总表，把剧本、参考图、提示词和每个素材登记进去，再开始批量生成。
注意
角色一致性仍不稳定，主角形象需要绕道 Nano Banana 才能修好；3D 预演花的时间比省下的还多。整套工具链要付多份订阅费，还要会剪辑。

Tim Simmons 在幕后视频里讲 Planet Hell 第一集的制作，重点放在出过的问题上。Seedance 2.5 一直不肯还原主角 Tom，他把形象放进 Nano Banana 处理一遍才解决，原因他自己也说不清。另一个角色换了人演，他觉得效果比原来更贴合故事。用 CozyClay 和 three.js 做的 3D 预演最后弃用了，花的时间比省下的多。画面里一颗大得离谱的子弹，是在 After Effects 里抠掉的，抠像由 Claude 完成。

可借鉴的是分工方式。生成、抠像、调色这些重复劳动交给 AI，剪辑和镜头取舍留给自己。他还专门做了一个「第二大脑」小组件，剧本、参考、提示词和每个素材都登记在里面。另外他发现，有时直接用平台界面比通过 MCP 从 Claude Code 调用更省事。

商业上，这一集由 OpenArt 赞助，频道观众有专属折扣链接，延续了「用 AI 创作，再做成教程内容」的模式。想照着做的人，可以从 07:37 的 MCP 生成部分和 15:50 起的三条经验看起。他还提醒一点：上传 YouTube 时关掉 Stable Volume 和 Voice Boost。

02｜Garry Tan：换上新模型后，删掉一个它已经不需要的 skill

谁说的
Y Combinator CEO Garry Tan，自己写了 GStack 等 agent 工具，2026-11-07 在 X 上发帖。
核心观点
他认为 agent skill 必须用评测驱动的循环来维护：每次换新模型都重新测一遍，多余的 skill 就去掉。
依据
他举了自己的例子：Opus 5.5 不带 /investigate 时效果更好，于是把这个 skill 删了。
对你的意义
给自己最常用的几个 skill 或提示词模板各准备几条固定测试任务，换模型时跑一遍有和没有的对比。
争议·条件
只有一个例子，也没有公开评测集。没有固定测试任务就做不了对比，只能凭感觉判断。

Garry Tan 在帖子里说，给 agent 写的 skill 需要评测驱动的开发循环。模型每一代都在变强，有些 skill 会变成多余，他刚因为 Opus 5.5 不用 /investigate 做得更好，就把这个 skill 删了。

这对正在积累提示词库、skill 和工作流模板的人有直接影响。我们平时只往里加东西，很少删。旧模型时代写的长串约束，放到新模型上可能反而碍事。比较稳妥的做法是给每个 skill 留三到五条有标准答案的任务，换模型时分别跑带 skill 和不带 skill 两个版本，看结果和耗时再决定去留。

这个判断有前提：任务能评测，结果能比较。写作风格这类主观任务比较难测，删之前最好让实际使用的人一起看结果。

03｜用 ChatGPT 把自己的画和照片做成 GIF 发群里

谁·场景
Lifehacker 作者 Khamosh Pathak，给 WhatsApp 群和社交平台做节日动图、表情包，也给自己的 JBL 音箱做了一张宣传图。
怎么用
写尽量详细的提示词，或者上传自己的手绘、照片；生成后继续用对话修改，比如调长短、删物体、换风格、放慢过渡。
结果
他说一次生成很少直接能用，改几轮后做出了愿意分享的 GIF。猫玩球、排灯节祝福这类轻松题材效果好，手冲咖啡这种需要真实物理细节的画面明显失真。
你可以试
拿一张自己的涂鸦或宠物照片，让 ChatGPT 做成循环动图，第一版出来后只改过渡速度这一项。
注意
手部位置会在帧之间跳动，物体和颜色会凭空出现。需要真实动作细节时，用免版权视频转成的 GIF 效果更好。

Khamosh Pathak 在 Lifehacker 上实测了 ChatGPT 新出的 GIF 生成功能。可以用文字起手，也可以上传手绘或照片作底稿，几秒就出结果，之后用对话继续修改。他觉得用自己的画做动图最有意思。给音箱做宣传 GIF 时，第一版过渡太生硬、动作也不合理，改过几轮才可以用。

这个工具的用处可以说得具体一点：节日祝福、群聊表情、小店简单的产品动图，都是不在意细节、追求好玩的场合。他用手冲咖啡做过对比：水壶不会画圈，水面上升不均匀，也没有气泡，比不上一段低清的真实视频。

建议的用法是：先选一个动作简单的题材，第一版出来后每轮只改一个问题，比如速度、多余的物体或风格，这样比一次重写整段提示词更容易收敛。

04｜创作工具开始内置 MCP，agent 和人可以接力干活

谁说的
Thariq，曾在 Anthropic 做 Claude Code，2026-11-06 在 X 上发帖。
核心观点
他喜欢这种模式：创作类 App 自带 MCP，让 agent 承担部分工作，熟练用户再在原有工具里协作、接手。
依据
他举了 Instagram Edits 和 Roblox Studio 两个例子。同一周，Tim Simmons 拍 AI 短片时也通过 MCP 从 Claude Code 调用 OpenArt 生成镜头。
对你的意义
查一下自己每天用的设计、剪辑或表格工具有没有 MCP 接口，先让 agent 做准备性的粗活，精修留在原工具里自己做。
争议·条件
Tim Simmons 的经验是，有些操作直接用平台界面更省事。MCP 只适合能说清楚、可以批量做的步骤。

Thariq 在帖子里说，他看好一种做法：Instagram Edits、Roblox Studio 这类创作工具直接内置 MCP。agent 先完成一部分工作，熟练用户在自己熟悉的工具里接着协作，不用把工作搬到新平台。

头条里的 Tim Simmons 就是这样用的：在 Claude Code 里通过 MCP 驱动 OpenArt 批量生成镜头，剪辑仍在 Premiere 里亲手做。他也提到，有些操作直接用平台更方便。

对做内容和做工具的人，判断标准可以是：哪些步骤能用一句话交代清楚、需要重复很多次，这些交给 agent；需要审美判断的部分留在人手里。做 SaaS 的人也可以想一想，自己的产品要不要开放 MCP 接口，好让用户的 agent 直接调用。

原文：Follow Builders (X)

今天可以做的一件事

打开你最常用的那份提示词或 agent skill，挑出用得最多的一个，写三条有明确合格标准的测试任务。用现在的模型分别跑「带 skill」和「不带 skill」两个版本，记录结果质量和耗时。不带反而更好的，就像 Garry Tan 那样删掉；带了明显更好的，保留下来，下次换模型时再测一遍。
