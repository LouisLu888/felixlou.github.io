01｜每天让 AI 写一篇指南，第一个 iOS App 月收入 4.1 万美元

谁·场景
Rasty Turek 做过 Google Gmail 团队，创业公司被 Amazon 收购过，Vaultaire 是他的第一个 iOS App：一个只在设备本地加密、没有服务器的文件和照片保险箱。
怎么用
代码和网站文字都由 Claude、Codex 等编程 agent 完成。他写了开源工具 Gum，把 Google Search 和 Keyword Planner 接进 MCP。agent 每天早上找出有曝光、没点击的关键词，写一篇指南，再加好内链。
结果
他说第一个月收入 66 美元，六个月后单月 4.1 万美元，累计下载超过 6 万。网站访问已占流量大头，从网站到下载的转化约 10%。60% 的购买是 39.99 美元终身版，贡献 80% 以上的收入。
你可以试
如果你的产品所在品类里，老牌对手只在应用商店竞争，可以先在 Search Console 或 Keyword Planner 里导出「曝光高、点击为零」的词，每天让 AI 针对其中一个写一篇真正解答问题的指南。
注意
这是一个需求早已被验证的成熟品类，他本人有多年安全行业背景。联合主持人 Gus 认为 SEO 在这里管用，是因为需求够窄，换成大众品类未必行得通。

Rasty Turek 在 Starter Story 里展示了 App Store 后台：周订阅 1.99 美元，年订阅 19.99 美元，终身版 39.99 美元。首日付费转化只有 5.47%，到第 35 天还在往上走。他说这类工具「首日转化最低，第 60 天最高」，和那些必须当场转化用户的热门 App 正好相反。

他的增长判断是：这个品类的对手大多有 15 年以上历史，App Store 排名追不上，但它们都不重视网页。于是他先做了一个列出功能的官网，再写「怎么在 iPhone 上保存照片」这类指南。现在的流程是 Keyword Planner 找词 → agent 写指南 → 用内链从已有流量页指向新页 → 等 Google 三四天收录。他还要求 agent 把下载按钮放在读者常读到的位置。他刻意每天只发一篇，不追求数量。

运营几乎零成本：App 用 Swift 和 UIKit 写，依赖 iCloud，统计用免费的 PostHog。他说现在剩下 99% 的工作就是 Claude 每天早上醒来写这篇指南。

02｜不请剪辑师，Claude 15 秒剪完一条 TikTok

谁·场景
Brooke Lacey 在科技行业工作超过 25 年，自己学剪短视频，TikTok 粉丝超过 29 万，还做了免费学 AI 的 App Zosha。
怎么用
在自己电脑上，让 Claude Code 调用 Whisper 转写、用 FFmpeg 剪切。她把自己的跳剪节奏、开头钩子和什么算好笑都教给了 Claude，还从评论区挖新脚本的选题。
结果
她说一条原始视频约 15 秒剪完，节目里有现场演示。她现在每周只发一条，不请剪辑师，粉丝仍在增长。
你可以试
如果你本来就用口播拍短视频，可以先装好 FFmpeg 和 Whisper，让 Claude Code 只做一件事：按转写删掉停顿和口误。再把自己满意的成片当范例，写进规则文件。
注意
前提是她多年自己剪片，清楚自己的节奏，能告诉 AI 怎么才算对。Claude 出错时，她要靠状态文件和重新提示把它拉回来。

在 How I AI 里，Brooke Lacey 现场让 Claude 剪了一条视频（08:51 起），然后逐步讲解剪辑链路（11:05 起）。这套工具都是现成的：Whisper 负责转写，FFmpeg 负责剪切，Claude Code 负责把两者串起来。

更值得学的是 15:58 起那一段：她怎么把自己的跳剪节奏、开头钩子和幽默感教给 Claude。剪辑速度靠工具，剪得像不像她本人，要靠这些规则。另一个做法是把评论区当选题简报，观众追问什么就拍什么，选题和后期都不再依赖别人。

32:43 起她谈到 Claude 让她失望的时候，以及怎样用状态文件把它拉回正轨。想照做，先从去停顿和口误开始，再逐步加入风格规则。

工作提效·本周演示·2026-10-18·US

03｜一条提示词，Opus 剪出带 3D 动画的成片

谁·场景
内容创作者 Riley Brown 拍完一段口播，16 分钟后发出了这条 Short。
怎么用
Opus 先分析转写，按口误和停顿剪切，再到 Twitter 搜索并抓取 B-roll。它用模板搭 Blender 场景，给每个镜头截图自查，把镜头、缩放和动画对齐到他说的每个词，最后加逐词字幕、音效和音乐，传到 Google Drive。
结果
他说成片 100% 由 Opus 5.5 剪辑。渲染在 RunPod 上完成，不到 20 分钟，费用不到 1 美元。
你可以试
先别急着复制全套。可以从「按转写剪掉口误」加上「让 agent 截图检查每一段」开始，后者是让 agent 自己发现画面问题的关键一步。
注意
他事先准备了包含四个镜头的 Blender 模板，还会用 RunPod 云渲染。他说下周的长视频重在讲原理，不会做成拿来就能用的 skill。

Riley Brown 在 这条 Short 的说明里列出了 15 个步骤。几处细节值得注意：Claude Code 会调用 GrokBot 在 Twitter 上找相关素材；提到某个品牌时，机械臂动画会把真实 logo 放到桌上；结尾的白板用 logo 和图形代替文字；他本人只在说话时出现在画面下三分之一，其余时间 B-roll 全屏。

可借鉴的结构是：模板定好画面空间，转写当时间轴，截图检查当质检。最后一步让 agent 自己看渲染结果，再修改，这比一次生成更可靠。

门槛不低，Blender 模板、云渲染账号和素材抓取都要先搭好。他说下周会出完整视频，讲清这套「小世界」底层怎么运作，让人能搭出自己的版本。

04｜Aaron Levie：agent 集群让算力成为干活的变量

谁说的
Box CEO Aaron Levie，在 X 上发帖。
核心观点
他认为很多工作只受投入时间的限制，卡在计划、执行、审查和协调上，所以今天做得远少于它们的经济价值。agent 集群能把这些工作并行化，理论上结果只取决于投入多少算力。
依据
他的依据是一个推理：只要 agent 能用工具、写代码、处理数据、有领域深度、能互相协调，设定好目标再投入足够的 token，就能解决复杂问题。他举了网络安全、生命科学和材料研究、交易、QA 测试、数据处理等领域。
对你的意义
盘点自己工作里「有价值但因为没人手而少做」的事，比如测试用例、竞品调研、数据清洗。挑一件小规模试试多个 agent 并行，看审查是否成为新瓶颈。
争议·条件
他自己说的是「理论上」，前提是模型在这些任务上已经足够好。并行之后，审查和协调的工作量能否同步下降，还要看具体领域。

Aaron Levie 在 这条帖子 里说，agent 集群会是「very big deal」。他的判断是：大量研究、发现、测试类工作并不缺需求，缺的是人去计划、执行、审查和协调。如果 agent 能接手这些环节，算力就成了决定产出的关键变量，相关行业的竞争格局也会变。

这是一个判断，还不是已经发生的事。对读者有用的是他给出的分类方法：找出那些多投时间就有更多结果的工作，它们最先能从并行 agent 中受益。上限取决于模型在这件事上够不够好，以及最终审查能不能跟上。
