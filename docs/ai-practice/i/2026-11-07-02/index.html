Garry Tan：换上新模型后，删掉一个它已经不需要的 skill

YC CEO Garry Tan 说，Opus 5.5 不靠 /investigate skill 反而做得更好，所以他把这个 skill 删了。

谁说的
Y Combinator CEO Garry Tan，自己写了 GStack 等 agent 工具，2026-11-07 在 X 上发帖。
核心观点
他认为 agent skill 必须用评测驱动的循环来维护：每次换新模型都重新测一遍，多余的 skill 就去掉。
依据
他举了自己的例子：Opus 5.5 不带 /investigate 时效果更好，于是把这个 skill 删了。
对你的意义
给自己最常用的几个 skill 或提示词模板各准备几条固定测试任务，换模型时跑一遍有和没有的对比。
争议·条件
只有一个例子，也没有公开评测集。没有固定测试任务就做不了对比，只能凭感觉判断。

Garry Tan 在帖子里说，给 agent 写的 skill 需要评测驱动的开发循环。模型每一代都在变强，有些 skill 会变成多余，他刚因为 Opus 5.5 不用 /investigate 做得更好，就把这个 skill 删了。

这对正在积累提示词库、skill 和工作流模板的人有直接影响。我们平时只往里加东西，很少删。旧模型时代写的长串约束，放到新模型上可能反而碍事。比较稳妥的做法是给每个 skill 留三到五条有标准答案的任务，换模型时分别跑带 skill 和不带 skill 两个版本，看结果和耗时再决定去留。

这个判断有前提：任务能评测，结果能比较。写作风格这类主观任务比较难测，删之前最好让实际使用的人一起看结果。
