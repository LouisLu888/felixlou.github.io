Figma 的 PM 们共用一个 Git 仓库，里面放了 31 个 AI 技能

Figma 增长 PM Ezra Mechaber 把 PM 的日常工作做成 31 个技能放进一个 Git 仓库，他每天用其中的「what's up」技能约六次，每天能归档约 10 个 Slack 频道。

谁·场景
Ezra Mechaber 是 Figma 的增长 PM，也是内部 PM OS 的作者之一。这套系统供公司六七十位 PM 使用。
怎么用
仓库里有一个 AGENTS.md、一组可复用技能和几个命令钩子。技能负责汇总 Slack、找相关同事、生成文档、做 bug bash。
结果
他说版本自动检查让 60 到 70 位 PM 保持同步。浏览器智能体在 bug bash 里找出了 1000 个 emoji 撑爆文本框这类边缘问题。
你可以试
挑一件你常跳过的例行工作，比如发布前通知客服，写成一个技能文件，放进团队共享仓库。
注意
需要团队愿意维护共享仓库，智能体也要有测试账号和工具权限。

在 How I AI 里，Ezra 说 PM OS 是围绕 PM 经常漏掉的工作设计的，例如发布前拉上客服、记录会议，目的是给每个流程定一个最低标准。Figma 大约 2000 人，光是找对协作者就不容易，所以有一个技能专门梳理团队结构，自动把相关的设计师、工程经理和负责人加为审阅人。每个人在私有子仓库里做自己的定制。

做 bug bash 时，他给智能体一个测试账号和一块写满测试场景的 FigJam 白板，让它记录发现的问题。增长实验 AutoXP 由三个智能体分工：一个找漏斗流失点，一个写新文案，一个准备实现。上线前人只审一次，之后系统自己分析结果，开始下一轮。

他还有一个习惯：对话跑偏时直接开新对话，把目标重新讲一遍，不在被污染的上下文里继续争论。最初这套东西跑在 Claude Code 终端里，现在他主要用 Codex。
