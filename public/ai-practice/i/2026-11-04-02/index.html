每两周让 Claude Code 给自己的用法做一次体检

投资人 Nikunj Kothari 用定时任务每两周跑一次 Claude Code 的 /insights，再对照收藏的行业做法升级自己的配置。

谁·场景
FPV Ventures 合伙人 Nikunj Kothari，在副项目里长期用 Claude Code 和 Codex。
怎么用
cron 每两周运行 /insights，看自己的配置哪里能改；再用 /playground 把 GitHub 项目架构和工作流画出来，并让 Codex 和 Claude Code 一起找死代码、热点路径和延迟问题。
结果
他把这称为一个自我改进的循环：一边是自己的使用记录，一边是收藏的行业新做法。
你可以试
用 Claude Code 的人，今天先手动跑一次 /insights，挑一条建议改进配置，两周后再跑一次对比。
注意
这套做法依赖 Claude Code 的内置技能，他也没有给出具体提效的数字。

Nikunj Kothari 在 X 上说，他最常用、但别人很少用的两个 Claude Code 默认技能是 /insights 和 /playground。前者他设成 cron 定时任务，每两周运行一次，告诉他怎样升级自己的设置；他再拿 X 收藏夹里别人搭「软件工厂」的新做法来对照。

/playground 他用来可视化：看陌生 GitHub 仓库的架构，或者在副项目里模拟一整套学习流程。他最近的用法是让 Codex 和 Claude Code 一起用这个技能，找出死代码、热点路径和可以降延迟的地方。

可借鉴的是复盘的节奏，用哪个具体命令是次要的。多数人配好工具后就不再动，定期让 AI 读一遍自己的使用记录，能发现没用上的功能。换成其他工具，也可以每两周导出一次使用记录，让模型给出三条改进建议。
