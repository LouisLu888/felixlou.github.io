Figma 的 PM 共用一个 31 个技能的 Claude Code 仓库

Figma 增长 PM Ezra Mechaber 把个人的 Claude Code 配置做成共享仓库 PM OS，收了 31 个技能，Figma 六七十位 PM 都在用。

谁·场景
Ezra Mechaber 是 Figma 的增长产品经理。他入职时发现，工程以外几乎没人用 AI 做正经工作。
怎么用
他和几位 PM 把自己的 Claude Code 配置整理成仓库 PM OS，里面有技能、hooks 和私有子仓库。他用 Codex 做 bug bash，还做了自动跑增长实验的 AutoXP，整个流程只设一个人工确认点。
结果
节目称 Figma 每位 PM 都在用这个仓库，覆盖六七十人；他每天要跑六次一个整理 Slack 的技能；AutoXP 第一次实验就找到了一个大收益。
你可以试
把你反复做的一件事（比如整理 Slack、写实验文档）写成一个技能文件，放进团队共享仓库，请同事挑毛病后再精简。
注意
前提是团队里的 PM 能用终端或 Git，他们后来也做了本地网页前端来降低门槛；自动跑实验需要成熟的实验平台和足够的流量。

在 How I AI 这一期里，Ezra Mechaber 说自己的目标是「在该偷懒的地方偷懒」。他把个人的 Claude Code 配置做成 PM OS，刻意做成一个仓库，不做成产品：技能和 hooks 放在共享部分，个人内容放进私有子仓库，一个仓库让六七十位 PM 保持同步。技能是一个个做出来的，经过同事「吐槽」后再删减，最后留下 31 个。

节目演示了几样东西：一个「幕僚长」式的配置；一个他每天跑六次、用来消化 Slack 的技能；用 Codex 做 bug bash，他说能发现自己注意不到的问题；还有 AutoXP，一个自动化的增长 PM，整个实验流程只留一个人工确认点，第一次实验就找到了大收益。后来他们把入口从终端换成了本地网页前端。

对大厂 PM 来说，比较现实的起点是先在自己身上跑通，再把最常用的几项交给同事试用。06:30 的演示和 22:08 的 AutoXP 部分可以先看。
