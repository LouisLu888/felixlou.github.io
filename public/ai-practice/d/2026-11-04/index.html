01｜一个月八万行：他在 Mac 上让 AI 写出 Windows 版

谁·场景
独立开发者 Tw93，Mac 软件 Mole（Swift + SwiftUI）的作者，要做一个原生 Windows 版（C# + WinUI 3）。
怎么用
代码和 Claude Code 留在 Mac 上，编译和运行交给 Parallels 虚拟机，用脚本把崩溃日志回传给 AI；设计 token 和 11 种语言的文案用脚本同步，再用一份 SYNC.md 核对两边功能。
结果
他说一个月写了 8 万多行代码、4000 多个测试，几位天使用户试用后反馈解决了不少痛点。
你可以试
如果你要维护两个版本的产品，先建一份对账表：每个功能写清已实现、刻意不同还是不适用，以及理由。
注意
Windows 签名绕不开：他买了 3 年 300 多美元的云端 OV 证书，签名会话闲置几小时就断，所以很难做成云端自动打包。

少数派作者 Tw93 在这篇文章里讲了 Mole Windows 版的做法。他先让 AI 分析十几万行 Swift 代码，能脱离 macOS 框架复用的不到 20%，所以决定从零重写。他把架构分成四层：Core 只依赖 .NET，用模拟的 Windows 文件系统测试；Platform 层开启 EnableWindowsTargeting 后在 Mac 上也能编译；ViewModel 和 Mac 版一一对应；只有最上层界面必须在 Windows 里编译。架构由他出思路，大部分实现交给 Opus 5.5。

调试也由脚本串起来。仓库作为共享文件夹挂进虚拟机，用 prlctl exec 远程编译、启动；程序崩溃时，Windows 只报一个 0xc000027b，Mole 会把真正的异常写进日志，打印出来给 Claude 读。需要点界面的地方交给 Codex 的 computer use，他自己只负责点系统确认弹框。虚拟机测不准的高分屏、电池和 SmartScreen，放到一台永不休眠的 ThinkPad 上回归测试，覆盖 400 多款软件的卸载和残留清理。

他的结论是：代码抽象没那么重要了，规则抽象更重要。两边同步时，他会记下对应的是 Mac 的哪个提交，防止 AI 跑偏。用 AI 做跨平台，可以先拿这两条规矩试。

02｜每两周让 Claude Code 给自己的用法做一次体检

谁·场景
FPV Ventures 合伙人 Nikunj Kothari，在副项目里长期用 Claude Code 和 Codex。
怎么用
cron 每两周运行 /insights，看自己的配置哪里能改；再用 /playground 把 GitHub 项目架构和工作流画出来，并让 Codex 和 Claude Code 一起找死代码、热点路径和延迟问题。
结果
他把这称为一个自我改进的循环：一边是自己的使用记录，一边是收藏的行业新做法。
你可以试
用 Claude Code 的人，今天先手动跑一次 /insights，挑一条建议改进配置，两周后再跑一次对比。
注意
这套做法依赖 Claude Code 的内置技能，他也没有给出具体提效的数字。

Nikunj Kothari 在 X 上说，他最常用、但别人很少用的两个 Claude Code 默认技能是 /insights 和 /playground。前者他设成 cron 定时任务，每两周运行一次，告诉他怎样升级自己的设置；他再拿 X 收藏夹里别人搭「软件工厂」的新做法来对照。

/playground 他用来可视化：看陌生 GitHub 仓库的架构，或者在副项目里模拟一整套学习流程。他最近的用法是让 Codex 和 Claude Code 一起用这个技能，找出死代码、热点路径和可以降延迟的地方。

可借鉴的是复盘的节奏，用哪个具体命令是次要的。多数人配好工具后就不再动，定期让 AI 读一遍自己的使用记录，能发现没用上的功能。换成其他工具，也可以每两周导出一次使用记录，让模型给出三条改进建议。

03｜讨价还价、退会员、排队等客服，交给 Grok 打电话

谁·场景
写 AI 实用教程的 Peter Yang，在测试 Grok 新的代打电话功能。
怎么用
用一句话交代目标、账户信息和底线，让 Grok 替你拨号、等待、谈判，再要回确认号或整理成表格。
结果
他给出了五个提示词模板，另外录了一段真实通话的演示视频。
你可以试
在美国有账单要谈的，可以照他的模板写：现在付多少、竞品报价多少、要什么结果、拿到确认号才算完成。
注意
目前只能拨美国号码；要交出账户信息，需要身份验证的环节可能仍得本人出面。

Peter Yang 在 X 上列了五个场景，每个都给了可以直接改用的提示词：

- 谈账单：「我每月付 Comcast 84 美元，竞争对手报价 49 美元，要求降价。」
- 退订阅：提供健身房账户信息，拒绝所有挽留优惠，拿到确认号。
- 等人工：给出航班确认码，一直排队到真人接听，要求全额退款。
- 订餐厅：周五 7 点 4 人，订不到的话 6 点到 8 点都行。
- 比价：给三家承包商打电话，问热水器更换的报价和最早开工日期，整理成表格。

这些提示词的共同点是写清现状、目标、可接受的范围和完成标准。范围让 AI 有谈判空间，确认号让你事后能核对。把账户信息交给 AI 之前，只提供这一次通话需要的信息就够了。

04｜笔记本上的 Qwen 只看权重，猜出了三个游戏

谁说的
开发者 Simon Willison，在博客上复现一篇热门论文的实验，2026-11-03。
核心观点
他认为这篇论文把两件事混在了一起：模型不借助工具读懂权重，以及模型写代码改进别的模型。前者更有意思，但外界的引申言过其实。
依据
他用 LM Studio 在本地运行 Qwen 3.8 27B，它猜对了 Pac-Man、Pong、Breakout，没猜出更冷门的 Freeway；Kimi K3.1 Pro 用 9 分 41 秒猜对了 Breakout。
对你的意义
看到「AI 已经能 X」这类热门论文，可以学他：拿论文公开的提示词，自己找一个模型跑一次。
争议·条件
他认为一个有经验的人拿纸笔，花足够功夫也能做到；Matthew Honnibal 批评这篇论文有误导性，Sean Goedecke 则指出改进小模型的步骤和人类研究员一样。

一篇论文称 GPT-6 Astra 能直接读写模型权重，Simon Willison 拿论文仓库里的提示词做了复现：把四个网格小游戏策略网络的浮点权重喂给模型，要求它不用任何工具，判断网络是为哪个游戏训练的。

他用自己写的 llm 工具配合 LM Studio，在笔记本上运行 Qwen 3.8 27B。默认的 8192 上下文会报错，超时也要调到 900 秒。Pac-Man 用了 46 分钟、4.3 万个推理 token，Pong 用了 1 小时 4 分钟，Breakout 用了 52 分钟，置信度分别是 72%、75%、88%。推理过程几乎看不懂。

他的态度值得照着做：承认能力确实存在，但不跟着下大结论。他说自己还没准备好宣布源代码时代结束。读者判断这类新闻时，看一个可以本地复现的例子，比看转发评论更有用。

05｜从逐条批准到默认放行，用不用 AI 的差距在拉大

谁说的
Box CEO Aaron Levie；Claude Code 早期团队成员 Cat Wu，两人都在 2026-11-03 发帖。
核心观点
Levie 的判断是：AI 已被广泛采用，但人和人之间产出的差距反而是历来最大，紧跟前沿和完全不关注，产出可能差一个数量级。
依据
Cat Wu 回忆，刚上线时多数人手动批准每个权限，主要拿 Claude 答问题、写测试；现在默认是信任 Claude 自动批准，用它做大型迁移和新产品。
对你的意义
检查自己交给 AI 的任务还停在哪一级：问答和写测试，还是能独立跑完的长任务。
争议·条件
5 到 10 倍是 Levie 按领域给的上限估计，不是测量结果，普通使用者到不了。

Aaron Levie 在 X 上写道，几年前即使在最适合 AI 的编程领域，熟练使用者大约能提效 30% 到 50%，还要花不少时间收拾模型的错误。现在模型能更长时间独立工作，工具支持同时用多个 agent，他估计提效上限已到 5 到 10 倍，并预计差距会继续扩大。

离开 Anthropic 的 Cat Wu 在告别帖里提供了一个使用侧的变化：她两年前用内部版 Claude Code 搭了一个强化学习环境，引导了几十个小时，自己没写一行代码。用户的习惯也从逐条批准权限变成了默认信任自动批准。

对读者有用的是这条变化路径：先放手让 AI 做小任务，建立检查机制后再放开权限和任务长度。

今天可以做的一件事

从你手上的工作里，挑一个以前只让 AI 回答问题的环节，改成一个它能独立跑完的小任务，比如让它整理一份表格并自己检查一遍。先学 Tw93，写一份三行的对账规则：输入是什么，产出应该长什么样，哪一步由你验收。做完后记下总耗时和你改了几处。两周后再做一次，看看这几处有没有减少。
