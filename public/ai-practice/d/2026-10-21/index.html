01｜一句“让它好玩得多”，AI 通宵跑了上千场模拟对局

谁·场景
开发者 Simon Willison 的业余项目：做一款能在手机上玩的 Command & Conquer 式即时战略游戏，用的是他自己很少写的 TypeScript。
怎么用
7 月用 Claude Fable 5 起步，先让 AI 提问再定 MVP。10 月换 Opus 5.5，在 Ultracode 模式（一个脚本同时调度许多 subagent）下只给了一句“让它好玩得多”。
结果
按 Claude 写的发布说明，它跑了一千多场模拟试玩：1200 场 AI 对 AI 比赛里，25 分钟还没分出胜负的比例从 14% 降到 0.9%；落后 800 以上资源后翻盘的比例从 24% 升到 46%。
你可以试
给 agent 布置复杂设计任务时，加一句“先调研并批评这个设计，我们商定修改后再动手”。
注意
一次通宵任务要跑很多小时；他几乎没审代码，只靠大量试玩验收，适合个人项目，不适合要对代码负责的生产系统。

Simon Willison 在本人博客复盘了 Battle Drones 的开发过程：12 个大版本，321 次提交，主要由 Claude Code 完成。前三版能看不能玩，他原本认为 coding agent 只能做出“像游戏的东西”。直到用 Ultracode 模式发出一句“让它好玩得多”，傍晚开始跑，第二天上午才拿到结果。之后一句“移植到 three.js”又跑了一夜，所有 3D 模型都是 Claude 用代码画出来的。

可借鉴的有两点。第一，让 agent 自己造评测：游戏好不好玩没法直接测，它就模拟大量对局，用“僵局比例”“翻盘率”这类指标代替。第二，他后来觉得自己出的设计太少，于是写了一段很长的地图设计提示，结尾要求先调研、批评，商定后再动手，结果做出了他认为最好玩的地图。

他的投入主要在试玩和提方向上。在线多人版本是后来补的，因为靠声音同步的近场多人模式“很让人头疼”。

02｜网站流量掉一半，试用反而涨了：Castos 用 Claude 批量做免费工具

谁·场景
Craig Hewitt，播客托管 SaaS Castos 的创始人，在 Niche Pursuits 播客讲 AI 搜索时代的获客变化。
怎么用
让 Claude 按播客主要完成的具体任务提出免费工具点子，团队筛出跟购买意图有关的，再按现成的页面模板让 AI 生成大部分页面，人工审核后上线。
结果
他说流量约为过去的一半，试用量上升，约 25% 的新客户可能来自这些新内容。WordPress 插件仍是另一大来源。
你可以试
列出你的目标客户付费前要做的 5 件小事，挑一件做成浏览器里能直接用的工具页，测一下注册转化。
注意
他说归因很难，一个客户可能多次接触才注册。这套做法建立在已有品牌、插件渠道和邮件列表的基础上。

Craig Hewitt 在 Niche Pursuits 访谈里说，Castos 过去靠“什么是播客”“最佳麦克风”这类大词文章获客。现在 AI 直接回答了这些问题，流量少了一半，团队转向两类内容：产品对比页和免费工具。比如上传视频文件、直接导出 MP3 的小工具。

工具页的流程是固定的：Claude 提点子，人评估购买意图和用途（获客还是拿外链），模板规定工具放在页面顶部、搜索内容放在下面，人工审核，然后通过邮件推送。他们给客户每月发一封，给非客户每周发一封。工具大多在用户浏览器里运行，几乎不增加服务器负担。

这套做法的前提是渠道。Castos 早年花几千美元买下装在约两万个 WordPress 站点上的免费插件，上线第一天就有付费客户。他的建议是先问未来的客户聚集在哪里。

03｜给 Claude Code 装个“旁观者”，它拦下了 45 个文件的误删

谁·场景
AI 工程师 Dan McAteer，在 Latent Space 撰文，分享几周来用 Claude Mods 定制 Claude Code 的体验。
怎么用
Mod 是在 Claude Code 里运行的 TypeScript/JavaScript 函数，可以拦截提示、工具调用、界面渲染等事件。可以用自然语言让 Claude 写 mod。
结果
You Should Know 提醒他：正在改的文件和另外约 45 个文件都有未提交的改动，丢弃演示修改会连带丢掉这些工作。他的 Next Steps Supervisor 在 10 月 15 日后的 111 轮对话里触发了 99 轮。
你可以试
在 Claude Code 里运行 /plugin，打开 Installed，启用默认关闭的 You Should Know，试用一周。
注意
触发太频繁就成了噪音。他说每次检查在 50k token 的会话上约消耗 5–6k 输入当量 token。mod 以你的权限运行，装别人写的要先看代码。

Dan McAteer 在 Latent Space 介绍了 Claude Mods。Anthropic 内置了 6 个，其中 You Should Know 默认关闭，它用一个旁路 agent 观察主 agent，把埋在执行记录里的关键信息挑出来。他自己写的 Next Steps Supervisor 在改了文件、跑了命令或调用 8 次以上工具后，列出需要注意的事项，并把下一步做成一键发送的按钮，已经收进他开源的 ModSmith。

他的判断是，agent 外壳中面向人的那一层，会决定什么时候打断你、给你看什么。ChatGPT 的 Intelligent UI 由模型决定界面，Cursor 的 PR 路由由团队写规则。Mods 让你和 Claude 一起设计这一层，但做得有没有用要自己负责。

他自己也遇到了问题：111 轮里有 99 轮被打断，他开始跳着看提示，这就失去了意义。设计这类提醒，触发条件要收紧。

04｜按故事点付工程师工资，AI 咨询公司 Tenex 做到 75 人

谁·场景
Tenex 联创 Alex Lieberman 和特别项目负责人 CJ Hess，在 Latent Space 讲如何帮大企业落地 AI。
怎么用
CJ 介绍 MetaHarness：一套共享的 skills、项目文档和 CLI，计划、验收标准、决策都提交进 Git，agent 回到任务时能读到“为什么这么做”。
结果
Alex 说担心的刷点数问题不是主要问题，因为 AI strategist 要对客户留存负责，会拒绝对客户没用的工作。客户需求正从外包开发扩展到全公司的 AI 转型。
你可以试
做 AI 咨询或外包的人，可以试一个按交付物报价的小项目，并把计划和验收标准写成 agent 能读的文档。
注意
Tenex 自己承认，这么多结构对单个项目的小团队可能太重。理解客户、设计架构这类工作很难拆成故事点计价。

在 Latent Space 访谈里，CJ 讲了他加入 Tenex 的原因：以前自己做咨询按小时收费，用 AI 后产出更快更好，收入反而少了。Tenex 按故事点付酬，于是产出越多拿得越多。随着模型变强，他直接写代码的时间变少，更多时间花在把客户背景整理成模型能用的形式。

主持人带来一个反例实验 Kill My SaaS：征集替代一款报价每年 4.3 万美元的讲者管理工具，收到 72 份作品。人类评委选出的冠军，在 AI 评委榜上只排第 19。“满足测试场景”和“人愿意用”是两回事。Alex 的反驳是：越往大客户走，替换成熟系统越贵、风险越大，小工具也得有人长期维护。

对咨询从业者，这场讨论给出了一个报价思路：卖结果，同时把维护责任算进交付范围。

05｜Mollick：从带着 AI 一步步做，到召唤一群 agent 再验收

谁说的
沃顿商学院教授 Ethan Mollick，在新书 Co-Existence 出版当天，于 One Useful Thing 回顾了 30 个月的 AI 进展。
核心观点
他在“半人马”（人和 AI 分工）、“赛博格”（人和 AI 交融）之外，提出第三种协作方式“召唤师”：按需召唤 agent、分派任务、评估结果。他认为人的优势在于深度知识、广度知识、品味和主动性。
依据
他引用的数据：GPT-4 发布以来，AI 能完成的任务长度翻了八番；研究生级题库每答对一题的成本从 30 美分降到 0.04 美分；已有 180 个模型超过当年的 GPT-4，其中 19 个能在手机上运行。
对你的意义
把一件需要几小时的研究加制图任务交给一个编排型 agent，只给两句方向，让它出多个版本，你负责挑和评。
争议·条件
他强调能力边界仍然参差不齐：AI 写长文依然很差。召唤师模式让人越来越难看清 AI 是怎样得出结果的。

Mollick 在本人文章里说，文中图表全部由 Opus 5.5 在 Claude Projects 里完成：一个编排 agent 分派子 agent 做调研、制图、排版和引用，原本要几小时的工作几分钟完成。他反复只说“做得更好”，AI 还指出他算错了月数，文章原本要叫“28 个月”。

这些属于他的判断和归纳，不是定论。对读者的影响在于分配精力：执行可以大量委托，人要留住的是判断结果好坏的能力。委托越多，越需要能检查结果的专业知识。

原文：One Useful Thing (Ethan Mollick)

今天可以做的一件事

从你的客户、同事或用户每周都要做的小事里挑一件（转格式、算一笔账、整理一份清单），交给 Claude Code 或类似工具，做成一个在浏览器里直接用的单页工具。动手前加一句“先批评这个设计，我们商定后再做”。做完发给三个真正有这个需求的人用，记下他们是否会再用、卡在哪一步。
