01｜手机原片进，15 秒后出一条剪好的 TikTok

谁·场景
资深技术人、TikTok 创作者 Brooke Lacey，在 How I AI 节目演示自己的剪辑流程。她大约每周发一条视频。
怎么用
Claude Code 编排 Whisper 转写、Python 和 FFmpeg。整套剪辑写在一个 TSV 文件里，每行是一个镜头的起止时间、景别和标签；她花了多轮指令，教 Claude 认出自己说笑话的节奏。
结果
她说成片约 15 秒生成，同一条素材能输出 15、30、60 秒和横版，不用上传素材，也不用打开剪辑软件。这套流程没让她发得更多，省下的是剪辑时间，一条视频不再占掉一整天。
你可以试
会用命令行的创作者，可以先让 Claude Code 用 Whisper 转写一条原片，生成一份剪辑点 TSV，自己核对一遍再交给 FFmpeg 输出。
注意
前提是你自己知道好的剪辑是什么样。风格要靠反复修正指令，一条提示词做不出来。

Brooke Lacey 在 TikTok 上有超过 29 万粉丝。她在 How I AI 节目里演示：手机录的原片交给 Claude Code，由它调用 Whisper 转写、Python 和 FFmpeg 处理，她说大约 15 秒后就得到带字幕、跳剪和推镜的竖版成片。

关键设计是把剪辑变成一份文本文件。TSV 每一行写一个镜头的起止时间、景别和标签，Claude 生成这份文件后，同一条命令就能输出 15、30、60 秒和横版几个版本。难的不在剪掉静音。她得教 Claude 认出自己的节奏：包袱前的停顿，一个词说完后在哪里切，重复录的几条里哪条最顺。这些是多轮修正出来的。

她还把每条视频和评论放在一起，让 Claude Code 找出观众在追问、争论什么，整理成下一批选题。她的提醒很直接：先懂这门手艺，才能交给 AI。她能教会 Claude，是因为自己清楚推镜该落在哪。更新频率她没有改，大约还是每周一条，省下的是每条的剪辑时间。

02｜找夜间育婴护士时，他发现中介也在翻 Facebook 群组

谁·场景
Startup Ideas Podcast 主持人 Greg Isenberg。孩子出生后他请夜间护士，中介承认人选是从 Facebook 群组里找的。
怎么用
先定细分、城市和筛选规则，再提示 Muse 搜公开 Facebook 群组、Marketplace 和 Instagram，把姓名、需求、价格、口碑整理进 Airtable 或 Google Sheets；用 Bland AI 的 AgentLine 给 agent 配电话号码，用来打电话、发短信。
结果
演示里 Muse 默认先去 CanadianNanny.ca 这类公开列表找人；他明确要求搜 Facebook 群组后，拿到了本地妈妈群、保姆招聘群里的帖子，他认为这些质量最高。这一期是演示加设想，他没有报告实际收入。
你可以试
选一个你熟悉的城市和服务，手动让 agent 找 20 条公开帖子，建一张表记下价格和口碑，试着撮合成第一单。
注意
Muse 不会自己想到去哪找，要你指定；私密群组需要本人加入。他用的是每月 100 美元的套餐，建议从免费版起步。

Greg Isenberg 在这期单人节目里讲了一个起因：孩子出生后找夜间护士，中介承认人选来自各城市的 Facebook 群组。他当场让 Meta Muse 找蒙特利尔时薪 30 加元的夜护。Muse 默认先翻公开招聘网站，他补一句「从 Facebook 群组给我找 20 个」，结果才转向本地妈妈群和保姆招聘帖。

他的做法分几步：定细分和城市 → 指定去哪找 → 清洗成自己的名单 → 由 agent 起草私信、打电话。电话号码用 Bland AI 的 AgentLine，他说约 15 美元。他的设想是成功撮合一单收几百美元；因为不用一组人去翻群，他认为毛利会很高。

他把这类生意分成四级：在别人的群里挖数据，拥有名单，拥有自己的群组或主页，最后做垂直软件把流程自动化。有两点限制：Muse 不会主动想到最好的数据源；买卖 Facebook 群组的做法，他自己也提醒先查平台条款。服务类撮合靠信任，名单里的人靠不靠谱，仍要你自己核实。

03｜AI 自动评测别用默认 0.5 阈值，调一下差很多

谁·场景
AI 评测顾问 Hamel Husain 给一个公寓租赁 agent 做自动评测，目标是找出预订失败、漏转人工这类错误。
怎么用
决策模型给每条日志打一个 0 到 1 的失败概率。他拿人工标注做对照，用五折交叉验证调阈值，要求精确率和召回率都不低于 80%，再用 Platt scaling 校准概率。两步都写成了能直接交给 coding agent 的提示词。
结果
3 个模型满足 80/80 的要求。Liquid d1 和 Clef Flash 调阈值后提升最大，但仍未达标。Clef Flash 有一组日志平均预测失败率约 8%，实际有 60% 出错。
你可以试
手里已有几十条人工标注 pass/fail 日志的团队，保存好模型分数，把他的调阈值提示词交给 coding agent，不需要重新调用模型。
注意
样本只有 100 条，任务故意定得很宽。F1 默认精确率和召回率同样重要，实际业务很少如此。

Hamel Husain 在博客里测试了几款新出的决策模型，看它们能不能替代 LLM judge 做便宜的自动评测。常见的问题是直接用默认阈值 0.50：如果一个模型给所有出错日志打 0.40、正常日志打 0.10，阈值设在 0.30 就能完美区分，用 0.50 却一个都抓不到。

他的流程是：先定最低线，再调阈值，最后看成本。用作自动告警时，他要求精确率和召回率都至少 80%，在满足这个条件的阈值里选 F1 最高的。达标的三个模型中，Perplexity 最便宜，OpenAI Decisions 效果最好，成本约为前者的 4.5 倍。想把分数当置信度用，还要先校准；校准对 OpenAI 反而略有反效果。

他建议实际使用时每种失败模式单独建一个判断器，预计那时模型之间的差距会缩小。他的习惯是先用效果够好的大模型，再试小模型能否以更低成本追平。

04｜Meta Muse Wonder 实测：处理工单很强，别让它碰前端

谁·场景
How I AI 主持人 Claire，用近 20 个工作任务对比 Muse Wonder 与 Opus 5.5、Astra、Fable。
怎么用
她搭了一个账单工单基准：模拟的 SaaS 环境里埋了账户关联错误、重复退款、改套餐和提示词注入，看 agent 能否一路处理到关单。
结果
Muse 修正了关联错误，处理了重复退款逻辑，改了套餐，起草回复并关单，所有埋点都解决了，也没被注入带偏。写邮件能贴合她两句话的简洁风格。前端设计忽略品牌规范、乱加 emoji，原型交互测试时按钮失效。
你可以试
把你岗位上一个真实工单或流程做成带坑的小测试，新模型出来先跑一遍再决定用在哪。
注意
复杂任务明显变慢。原型常常能做到八成，后面的视觉打磨和交互完整度做不好。

Claire 在 How I AI 里实测 Meta 新模型 Muse Wonder。它最强的是长链条 agent 任务：一个办法不行就换一个，直到达成目标。复杂任务上它花的时间更长，结果也更好，她认为时间和质量的对应关系比竞品更清楚。

可借鉴的是她的账单工单基准：模拟真实 SaaS 后台，故意埋入账户关联错误、重复退款和提示词注入，要求 agent 从修正、改套餐、写回复一直做到关单。这种测法比聊天对比更接近你会交给 agent 的真实工作。

短板也很具体：前端默认粗衬线字体、蓝紫配色和千篇一律的 SaaS 布局，ChatPRD 改版时还弄坏了图片显示。剪视频时它能挑对 40 秒片段，但字幕位置和音频处理不到位。她的结论是把它放进几个 agent 工作流里试，但不做日常主力，也不用在前端上。

05｜一次纽约行、一份报税，各开一个用完就归档的 AI 对话

谁·场景
风投合伙人、两个孩子的父亲 Nikunj Kothari。他用过 Wabi 1.0 但没坚持下来，这次试用 2.0 版。
怎么用
一个总调度 agent，按事务自动生成单一用途的对话：纽约出差、2025 年报税、孩子学校。单个对话可以分享给家人。
结果
他说纽约行程的对话是 agent 看到航班后自己建的，需要时提供帮助，回来后自动归档，报税也是这样。按他的说法，下载后马上就用上了。
你可以试
用你手上的个人助手，试着按事务分开对话（一次旅行、一次报税），事情办完就归档，家庭事务的对话和伴侣共享。
注意
要让它主动开对话，就得给它看行程等个人信息的权限。他的批评是它太主动，配套应用也还需要打磨。

Nikunj Kothari 在 X 上写了自己用 Wabi 2.0 的体验，并说明没收钱也没投资。他把个人 agent 分成两类：Muse 这种单线程助手，事情一多就混在一起；自己搭的多会话 agent 能共享上下文，但对话一直留着。

Wabi 的做法是一个总调度加按事务开的临时对话。他去纽约前，agent 根据看到的航班自动建了行程对话，回来后归档；2025 年报税也单开一个。孩子学校的对话分享给了妻子，两人看的是同一份上下文。

对普通家庭，可以借鉴的是组织方式：一件事一个对话，办完就收起，需要配合的那件事拉上伴侣。代价是要让 agent 主动建对话，就得开放航班、日程这类信息。他自己的批评是它太主动了。

06｜Box CEO：模型越强，垂直 AI 越有差异化空间

谁说的
Box CEO Aaron Levie，2026 年 10 月 20 日在 X 上发帖。
核心观点
他认为模型能力有限时，应用层只能做套壳；现在 agent 要调用工具、长时间运行、多个 agent 协同，还要接行业数据、按领域路由模型、改造客户流程，专门化的价值反而上升。
依据
他的依据是一组变化：任务从一问一答变成长时间运行，从聊天框变成要接入真实工作流、需要变更管理的系统。他预计安全、生命科学、医疗、金融、制造会出现各岗位的自主系统。
对你的意义
做垂直工具或咨询的人，可以把差异化放在行业数据、工作流编排和落地实施上，单靠提示词撑不住。
争议·条件
他自己也说，离大模型公司的核心用途越近，这条路越难走。这是预测，不是已经发生的事。

Aaron Levie 在 X 上谈应用层的「苦涩教训」：模型越来越强，怎样把这些能力真正用进企业？他的判断（2026-10-20）是专门化的空间会变大。

他的理由是：模型能力有限时，应用层能做的只是加一段提示词、做一点检索，然后把输出交还给用户。现在 agent 要用工具，任务能跑几小时甚至几天，多个 agent 要围绕一个目标协同，还要接行业数据、按领域选模型，实施也成了真正的流程变革，不再是让人往聊天框里打字。这些环节都需要行业知识。

对做 Micro SaaS 或 AI 咨询的人，这意味着价值更多在熟悉某个行业的流程和数据上。他也划了边界：做的事离大模型公司的核心用途越近，越难守住。

今天可以做的一件事

找一件你每周都要重复做的事，比如剪视频、写周报或处理工单，把你的修改规则写成一份文件：哪里要删，什么算合格，常见错误是什么。今天就用它让 AI 做一遍，在文件里补上你改动的地方。Brooke 教会 Claude 剪出自己的节奏，Hamel 把评测阈值调到可用，靠的都是把自己的判断写清楚，再拿真实结果去对照。
